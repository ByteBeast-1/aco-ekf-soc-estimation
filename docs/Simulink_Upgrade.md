# Simulink / MATLAB Upgrade Notes

This documents the rebuild of the MATLAB/Simulink side of the project, the measured results, and what is
still needed to call it an industry-grade model-based-design (MBD) workflow.

## What was wrong before

| Issue | Effect |
|---|---|
| `sota_bms_aco_ekf` used a regression trained on one dataset applied to a different, simulated plant | SOC error up to 33.9 %, estimated voltage down to -18 V |
| ARX-to-RC parameter mapping in the RLS saturated at its clamps | R0 estimate stuck at 0.15 ohm (true value ~0.012 ohm) |
| "NASA hardware" replay used `data/NASA_B0005.csv`, which is **synthetic** (generated by `nasa_dataset_loader.py`) | The model never saw real cell voltage |
| Algorithm code pasted as strings into the builders; parameters duplicated in 3-4 places | Hard to review, test or keep consistent with Python/C |
| `randn()` unseeded; Q*/R* hard-coded constants | Non-reproducible; the ACO result was not actually used |
| Plant and estimator used identical equations/parameters | "Inverse crime": too easy a test |

## New architecture

```
simulink_matlab/
  lib/                      single source of truth, plain .m files (codegen-style MATLAB)
    bms_params.m            every cell / sensor / filter / diagnostic parameter
    bms_plant_step.m        2-RC Arrhenius plant (with capacity & resistance mismatch)
    bms_sensor_step.m       seeded noise, 1 mV ADC, fault injection (I offset, V glitches, T open)
    bms_est_step.m          3-state Joseph EKF + diagnostics; bit-mask adaptation modes
    bms_aco_tune.m          MO-ACOR tuner -> writes lib/bms_tuned_data.m (consumed by the models)
    bms_nasa_load.m         real NASA .mat discharge -> 1 Hz
    bms_nasa_calibrate.m    OCV fit on one real cell -> lib/bms_nasa_cal_data.m
    bms_simulate.m          pure-MATLAB closed loop (tuning, Monte Carlo, back-to-back reference)
  build_bms_models.m        regenerates both .slx files (thin MATLAB Function wrappers only)
  bms_setup.m               model InitFcn: path + scenario variables (overridable)
  run_bms_regression.m      automated verification (22 checks)
```

* `advanced_bms_aco_ekf.slx` - simulated plant + faultable sensors + ACO-tuned EKF, 8 scopes, diagnostic code.
* `sota_bms_aco_ekf.slx` - replays a measured NASA discharge; conventional EKF and adaptive EKF run side by side.
* Scenario variables (`BMS_Seed`, `BMS_FaultMode`, `BMS_SOC_Guess`, `Drive_Profile`, `NASA_Replay`, ...) live in the
  base workspace, so `Simulink.SimulationInput` can sweep them.

## Verification (run `run_bms_regression`)

Calibration and tuning data (B0006 discharges #1 and #60) are disjoint from the evaluation data.

| Suite | Result |
|---|---|
| Back-to-back, Simulink vs library | max difference 4e-12 % (both models, both controllers) |
| Monte Carlo, 40 randomised synthetic runs (init error +-20 %, capacity 0.90-1.05x, resistance 0.9-1.4x) | EKF mean MAE 0.48 %, worst run 1.15 %, worst instant 1.85 %; Coulomb counting 10.7 % |
| Fault injection (t = 900-1200 s) | glitches (code 8) and thermistor open (code 2) detected; max error unchanged vs fault-free 0.40 %; 0.25 A current offset (silent) raises max error to 0.75 % |
| Real NASA, fresh unseen cells (B0005 #1, B0007 #1) | MAE 0.66 % / 0.93 % (Coulomb counting 10.7 % / 11.9 %) |
| Real NASA, aged cycles (cap. 1.36-1.67 Ah) | MAE 2.3-4.9 % |
| Real NASA CC-CV charge cycles (fresh B0005 #1, B0007 #1) | EKF MAE 3.6 % / 3.7 % vs Coulomb counting 6.7 % / 7.3 % (reference assumes the cycle starts near empty, so aged-cycle charges are not used) |
| Online capacity (SOH) estimate, 7 unseen cycles | mean abs error of capacity ratio 0.069 (range 0.03-0.12) |

### Ablation (mean MAE %, lower is better)

| Estimator | synthetic (model-matched) | real NASA (unseen) |
|---|---|---|
| ACO-tuned EKF | 0.364 | 2.705 |
| + scalar-RLS R0 tracking | 0.278 | 3.636 |
| + Sage-Husa R | 0.383 | 2.686 |
| + Sage-Husa Q | 0.383 | 6.434 |
| + RLS + SH-R | 0.329 | 3.263 |
| all adaptation | 0.407 | 6.364 |
| + online capacity (SOH) state | 0.566 | **2.451** |
| + Sage-Husa R + capacity | 0.586 | 2.474 |

**Finding:** adaptation helps only when the model structure is right (R0 tracking on synthetic data). On real
cells it absorbs capacity fade and OCV mismatch into the wrong parameter and degrades accuracy. The default
adaptive estimator therefore enables only Sage-Husa R (`P.sota_mode = 2`), which is neutral-to-slightly better.
The other modes remain selectable in `bms_params`.

**Capacity (SOH) state (mode bit 8).** The EKF carries a 4th state, the capacity ratio Q_true/Q_nominal
(`bms_est_step.m`, `bms_est_init.m`). It is frozen (zero variance) unless bit 8 is set, so every other mode is
bit-for-bit unchanged. On real cells it gives the best mean accuracy (2.45 % vs 2.71 %; B0005 #120 4.89 -> 3.09 %)
and a rough SOH reading, but on fresh cells it is worse (e.g. B0005 #1 0.66 -> 1.16 %) and on the model-matched
simulation it is worse too. Because capacity is only weakly observable in one constant-current discharge, the
estimate is biased by up to about 0.1 by cell-to-cell OCV differences. It is therefore an optional mode
(`sota_mode = 10`), shown in `sota_bms_aco_ekf` as the third, bottom controller, not the default.

## Known limitations

* Aged-cell error (up to ~9 % instantaneous, 5 % MAE) is a capacity-fade signature: the filter assumes the
  nominal 2.0 Ah. The optional capacity state reduces it but is not accurate enough to be the default.
* No dynamic *driving-cycle* data is available locally (`data_raw/BatteryAgingData.zip` only duplicates the three
  `.mat` files). Validation on CALCE / Oxford / Panasonic drive cycles needs those datasets downloaded.
* NASA data is a constant-current 2 A discharge sampled every 9-19 s and linearly resampled to 1 s; it does not
  exercise dynamic driving behaviour or low-temperature operation.
* The 'synthetic' variant still uses the paper's OCV polynomial, which reaches 4.59 V at 100 % SOC (above the
  4.2 V limit of a real Li-ion cell). It is internally consistent but not physical.
* MATLAB Coder / Simulink Coder are licensed but not installed here, so C generation and
  software-in-the-loop equivalence with `c_firmware/bms_ekf.c` were not verified.
* `data/NASA_B0005.csv` (and `run_sota_ultimate_simulation.m`, `nasa_benchmark_runner.py`, which read it) use
  synthetic data. Use `data_raw/*.mat` via `bms_nasa_load` for real data.
